2. Données — exemples concrets « pourquoi ? »

Exclu

NomPrenom, PersonneAPrevenir

Pourquoi ?

Identité directe → art. 9 RGPD + secret médical. Jamais dans les features ML.

Où ça va : coffre identité (hors curated).

Exclu

Readmission30j (en entrée)

Pourquoi ?

C’est la cible. L’utiliser comme feature = tricher (fuite de label).

Usage : uniquement pour entraîner / évaluer.

Flag only

RégimeAssurance, SituationFamiliale

Pourquoi ?

Proxies socio-économiques individuels → risque de biais. Le sujet interdit les données socio individuelles non collectées à l’hôpital.

Usage : audit / biais, pas le score opérationnel.

Autorisé

DureeSejour, GHM, diagnostics, bio…

Pourquoi ?

Signaux cliniques de parcours, disponibles à la sortie, justifiés pour prioriser le suivi.

Garde-fou : cutoff ≤ DateSortie + flags qualité.

Ajout contrôlé

INSEE agrégé (territoire)

Pourquoi ?

Proxy territorial agrégé (pas individuel). Préfixe INSEE_ajoute_, fichier dans data/external/, sujet non modifié.

Usage : contexte / biais ; pas d’identité.

Hors cohorte ML

Sorties ≠ Domicile

Pourquoi ?

Décès, transfert, EHPAD, HAD : le besoin « suivi à domicile à 30 j » ne s’applique pas de la même façon.

Usage : audit descriptif uniquement.

4. Modèles — pourquoi retenir / écarter

Retenu

LightGBM

Pourquoi ?

Meilleur PR-AUC test sur splits patient-level (classes déséquilibrées). Optuna sur validation.

Gardé

Logistic / RF / référence

Pourquoi ?

Baseline et alternatives interprétables. Comparaison honnête sur les mêmes splits.

Comparé

MLP (réseau)

Pourquoi prudent ?

Petit n (~480 séjours) → risque de surapprentissage. Présent pour la comparaison CIF, pas comme choix « safe » par défaut.

Métriques

PR-AUC + seuil F2

Pourquoi ?

Prévalence faible → accuracy trompeuse. On privilégie le rappel (ne pas rater une sortie à risque) via F2 pour le seuil.

Rapports : models/benchmark/score_sortie_benchmark.html · Registry : models/registry/score_sortie_latest.json

5. Produit & privacy — choix structurants

Choix

Deux parcours UI

/cisia = brief jury (score, SHAP, biais, registre). /soignant = illustration lits — clairement secondaire.

Choix

LLM 100 % local

Brief sur CR masqué. Aucune donnée patient envoyée au cloud. Bind 127.0.0.1.

Choix

Mesurer les biais

Âge, sexe, territoire : on affiche les écarts, on ne les cache pas (/cisia/biais).

Hors périmètre

Décision clinique réelle

Données synthétiques. L’outil priorise un suivi ; il ne remplace pas le médecin.
